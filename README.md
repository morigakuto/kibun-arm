# きぶんのあるアーム — 制作ランブック

**コンセプト**: 手をかざすと、気づいて、こちらを見て、寄ってきてスリスリするSO-101。
その「親しみ」はコードに書かず、リーダーアームで**演じて見せた**デモからの模倣学習だけで転写する。

> ELEGNT (Apple, DIS'25) は表現的な動きをアニメーターとHRI研究者が手で設計し、**事前収録した軌道を再生した映像**を
> 21人に見せて評価した。学習も方策も自律性もない（式 `max F(τ)+γE(τ)` は枠組みの提示であって、解いていない）。
> 論文自身が結論で "Future work will integrate these design insights into a **generative framework**" と書いている。
> 本作はその未着手部分を、**飼い主が演じて見せる**という方法で埋めにいく。

**実験デザインは ELEGNT のユーザースタディをそのまま踏襲する**（F条件 vs E条件）。
同じ視覚入力・同じゴール状態（手に触れる）・違うのは行き方だけ。

**ゴール状態は両条件とも「差し出された手に接触する」。** スリスリは expressive が接触を作り・保つ
*やり方*であって、ゴールではない（ELEGNT の Remind Water と同じ構造: E = F + 表現で、E の方が動作が多い）。

| | `functional` (γ=0) | `expressive` (γ>0) |
|---|---|---|
| タスク文字列 | `Move to the hand` | `Notice the hand and nuzzle it affectionately` |
| 待機 | **完全静止** | 探すゆらぎ |
| 手が出た時 | 溜めなし・視線なし | 頭だけ向ける → 溜め → 顔を見る |
| 経路 | **最短距離・等速**（加減速を殺す←機械らしさの正体） | わずかに弧、加減速あり |
| 接触 | 触れて**止まる**（1秒） | 沿わせてスリスリ2〜3往復 |
| 接触後 | そのまま終了 | もう一度顔を見上げる |
| 長さ | 8〜12秒 | 20〜25秒 |

接触点は両条件で同じ場所にすること（ゴール状態を揃えるのが論文の統制）。
「動作は同じで質だけ違う」版（機械的にスリスリする）は**採らない** — 差が小さくなって学習で分離しにくく、
観客にも伝わりにくい。差は大きいまま保つ。

```
Mac (このマシン)                     HF Hub                Ubuntu RTX 6000
テレオペ録画 → 品質確認 → push  ──→  datasets  ──→  ACT×2 + SmolVLA 学習
rollout (mps推論・実機デモ)     ←──  models    ←──  自動push
```

### 手と服の基準

**マーカー・QRは貼らない。** (1) ポリシーが手ではなく**マーカーを追う**ようになり隠れた瞬間に崩壊する
(2) 見た人に「実際には見えていない」と即バレする（ELEGNT §5.2.3: 能力と動きのミスマッチは最も嫌われる）
(3) 「書いてない、演じただけ」という主張を自分で否定する。
SmolVLA の視覚バックボーンは web スケールで**手**を学習済みで、静止した机の上で唯一動く肌色の物体は極めて強い信号。

| 項目 | 基準 | 理由 |
|---|---|---|
| 袖 | **肘まで捲る／半袖**で固定 | 素肌は他人の手にも一番移りやすい。特定色の袖はその色を覚える |
| 色 | 机（白）とアームの色を避ける | 1カメラなので背景と混ざると致命的 |
| 柄・ロゴ | 無地 | 60本しかないので余計な変動は全部ノイズ |
| 時計・指輪 | **外す** | 明日のデモまで同じ状態を保てないなら最初から無しに |

明日のデモも同じ人・同じ服でやる前提。

### 借りたアーム・別の場所で録るときの追加ルール

- **キャリブレーションは全録画の前に1回だけ。途中でやり直すと action 空間がズレて過去のエピソードが使えなくなる**
- **録画したアームでデモする**。関節オフセットは個体ごとに違うのでポリシーは別個体に移らない
- **カメラは養生テープで固定**。1カメラ構成なのでズレたら全部やり直し。ケーブルも固定
- **可動域の下見**: 手を置く9点すべてに (a) アームが届くか (b) カメラに映るか
- **光を固定**: ブラインドを閉めて人工照明だけに。3時間で日が回ると条件の手掛かりとして学習される
- リミットに突っ込ませない。終わったら持ち主に「キャリブレーションし直した」と伝える

## 0.5 テレオペ演技プロトコル

### SO-101 の関節 ↔ 生き物の動き

| 関節 | 意味 | 使いどころ |
|---|---|---|
| `shoulder_pan` | **横を向く** | 気づく（横に手が出た時）、アイドルの捜索 |
| `shoulder_lift` + `elbow_flex` | **前に伸びる／引っ込む・沈む** | 接近、のけぞり |
| `wrist_flex` | **頷く／見上げる・うつむく** | 気づく（正面）、**顔を見る**、覗き込み |
| `wrist_roll` | **首をかしげる／頬ずり** | スリスリ本体 |
| `gripper` | 使わない（常時閉） | 爪ではなく鼻先に見せる |

> グリッパは**閉じきる手前**で止める（閉じきるとサーボが押し続けて発熱）。
> リーダーのトリガーを軽く輪ゴムで留めると3時間握らずに済む。

### 練習の順番（20分）

**① 画角と可動域の下見（3分）** — 手を9点×高さ2段に置いて全部映るか・届くかを確認。
**★1カメラなので「接近中にアーム自身が手を隠さないか」を必ず見る。** 隠れるならカメラを45°ずらす。
机に養生テープで四隅の目印を貼ると9点を再現できる。

**② ホームポーズを決める（2分）** — 全エピソードの開始姿勢。少しうつむいた、寝ている動物のような格好。

**③ アイドル＝「探している」ゆらぎ（5分）** — `shoulder_pan` をゆっくり左右、`wrist_flex` で軽く上下。
1〜2秒で1往復。一定のリズムにしない、たまに止まりかける。※ `functional` では**完全静止**にする。

**④ 気づく＝溜め（5分）★作品の出来を決める** — 横に出たら `shoulder_pan` だけ、正面なら `wrist_flex` で
0.3〜0.5秒かけて手の方へ。**体はまだ伸ばさない。** 0.2秒ためてから `shoulder_lift`/`elbow_flex` で伸び始める。

**⑤ 顔を見る（3分）★親しみの最大要因** — 接近の前に一度、`wrist_flex` で頭を上げてあなたの顔を見る。
スリスリの後にもう一度見上げる。ELEGNT §6 は gaze を joint attention の印と特定し、P15 は
「人同士がするように自分を見て」くれないと **"there was a lack of connection"** と述べている。

**⑥ 接近とスリスリ（5分）** — 接近は直線ではなく**わずかに弧**。押し込まず、`wrist_flex` で高さを合わせて
`wrist_roll` を左右に振って頬ずり2〜3ストローク。離れる時はすぐ引かず少し留まる。

**⑦ 追従（3分）** — スリスリしながら手をゆっくり動かし、ついていく。デモの決定的なカット。

## 1. 録画（約2.5時間、60本）— **2パスに分ける**

```fish
cd ~/cinaps/kibun-arm/scripts
# --- 1st pass ---           (→で次、←で撮り直し、ESCで終了)
./10_record.fish expressive 20
./10_record.fish functional 10
# --- 2nd pass ---           (再実行すると自動で --resume=true になり追記される)
./10_record.fish expressive 20
./10_record.fish functional 10
```

**1st pass の expressive を録り終えたら、すぐ push してスモークテストを回す**（残りを録りながら裏で回せる）:

```fish
./30_push_all.fish expressive
# 学習マシンで: STEPS=8000 ./train_remote.sh act expressive   → 約15分
# 戻ってきたら: ./40_rollout.fish TECHIdesu/act_nuzzle_hand_v1_expressive expressive 3
```

見るのは**「手に寄っていくか」だけ**。ここでコケていたら残りを同じやり方で録っても無駄なので、
その場で撮り方を直す。60本録ってから朝に気づくのが最悪のシナリオ。

> **なぜ2パスか（重要）**: 連続で録ると**時間と条件が完全に相関する**。3時間のうちに日照・カメラのズレ・
> サーボの温まり・そして**あなたの演技の上達**が必ずドリフトし、それが条件の手掛かりとして学習されうる。
> 本番では光は1つしかないので、その手掛かりが消えて分離しなくなる。2パスなら各条件が
> 「序盤の下手な自分」と「終盤の上手い自分」を等しく含む。**コストはゼロ。**

**expressive 40本の内訳**: 14本=3x3グリッド静止手 / 14本=スリスリ中に手をゆっくり移動（**追従を教える。
再生じゃない証明ショットになる**）/ 8本=ランダム位置・高さ / 4本=手を一度も出さないアイドル。

### キー操作 — 時間ではなく自分で区切る

タイムアウトは保険（既定10分）で、実質**`→` を押すまで無制限**。1エピソードにつき**2回**押す。

| キー | 動作 |
|---|---|
| `→` / `n` | 今のフェーズを終える。1回目=演技終了、2回目=リセット終了して次のエピソードへ |
| `←` / `r` | 今のエピソードを破棄して撮り直し |
| `Esc` / `q` | 保存して終了（長いタイムアウト中でも即座に効く） |

> **⚠ 連打禁止（データセットが壊れる）**: `exit_early` は単なるフラグで、フェーズの切れ目に
> 余分な押下が残ると次のフェーズが即座に終了し、**1フレームだけのエピソード**ができる。
> それが保存時に pyarrow のクラッシュ（`stats/... expected length N but got N-1`）を起こし、
> **`meta/episodes/` が書かれずセッション全体のデータが読めなくなる**（2026-08-08 に9本を失った）。
> **1回押したら音声アナウンスを聞いてから次を押すこと。**

> **⚠ `Record loop is running slower (X Hz)` が出たら即中断**: フレームが落ちて時間軸が歪む。
> この作品は速度プロファイルが命なので致命的。原因は Rerun 表示（実測 20Hz→9.2Hz）。
> 既定で `display_data=false` にしてある。画角確認したい時だけ `DISPLAY_DATA=true` を付ける。

音声が「Recording episode N」＝演技フェーズ、「Reset the environment」＝リセットフェーズ。
**リセット中は録画されていない**ので、アームをホームに戻して手をフレーム外に構えるまでゆっくりでよい。
macOSで矢印キーが効かない場合はアクセシビリティ権限の問題 → **n / r / q** を使う（同じ動作）。

短くしたい時は `EP_TIME=180 RESET_TIME=60 ./10_record.fish expressive 20`。

**エピソードの尻に無音区間を作らない。** 余韻が終わったら**すぐ →**。静止フレームを残すと chunk が汚れる。
**最初の2〜3本は捨てる前提**で感覚を掴む（後で `./45_inspect.fish` で長さを見て
`./20_delete_episodes.fish expressive "[0, 1]"`）。

> **⚠ データセット名にタイムスタンプが付く**: `lerobot-record` は新規作成時に repo_id へ
> `_20260808_151839` のような日時を自動で付ける（`configs/dataset.py` の `stamp_repo_id`）。resume 時は付けない。
> スクリプト側で `kibun_repo`（env.fish）が最新のものを自動解決して `--resume` するので、
> **同じコマンドを再実行すれば必ず同じデータセットに追記される**。
> Hub へは `30_push_all.fish` がタイムスタンプなしのきれいな名前で公開する。

## トラブルシュート

- **`ConnectionError: Failed to sync read ... There is no status packet!`**: モーターバスの一過性の通信断。
  録画は落ちるが**保存済みエピソードは無事**（`finalize` が走るため）。復旧手順:
  1. `./46_ping_arms.fish` で全モーターが応答するか確認
  2. 応答するなら、そのまま `./10_record.fish expressive 20` で再開（自動 resume）
  3. 応答しないなら電源とデイジーチェーンのケーブルを見る（AGENT_GUIDE §4.5: 消灯=配線、点滅=過負荷/電圧違い）
  - **再発防止**: アームが動いてもケーブルと電源ジャックが引っ張られないよう養生テープで固定する。
    根本原因はほぼ物理接触。lerobot 側は `num_retry=3` を入れて一過性なら耐えるようにした（下記）
- **⚠ 再開時にキャリブレーションを聞かれたら必ず ENTER**（`c` ではない）。
  現在の `follower.json`/`leader.json` は 2026-08-08 にこのアームで作ったもの。
  ここで `c` を押すと原点が変わり、**録画済みエピソードと action 空間が食い違って全部無駄になる**
- **Feetechタイムアウト**: まずモーターの赤LED。消灯=配線、点滅=過負荷 or 電源電圧違い（AGENT_GUIDE §4.5）
- **カメラが映らない/入れ替わる**: `00_find_cameras.fish` → `env.fish` のindex修正
- **テレオペ開始時にフォロワーが飛ぶ**: `max_relative_target: None` なので上限なし。**開始前にリーダーを
  フォロワーと同じ姿勢に合わせる**
- **サーボ発熱**: グリッパを閉じきらない。エピソード間で脱力させる

## ELEGNT根拠メモ（作品文に使う）

**主張の骨格**

- 定式化: `max F(τ) + γE(τ)`（Eq.3）。ユーザースタディは γ=0 vs γ>0 の比較（本作が踏襲した設計）
- **学習は一切ない**: "iteratively designed and refined **pre-recorded** robot movement trajectories...
  implemented using the off-the-shelf 6-DOF WidowX controller"（§4.2）。参加者が見たのは実機ですらなく**動画**
- 論文自身の future work: §6 "personalized behaviors" / §7 "**generative framework**" ← 本作の位置
- 結果: 表現あり M=56.16 vs 機能のみ M=28.77 (t=19.85, p<0.0001)。**最大の差は Perceived character (t=10.58)**、
  次いで Human-likeness (9.32), Engagement (8.80), Sense of Connection (8.50)
- 表現的動きは**social-orientedなタスクほど効く**（H2支持。function-oriented では有意差なし）
- 参加者は表現的ロボットを自発的に "**puppy**" "**child**" "**friend**" と呼んだ ← 「親しみ」の正体

**演技を縛る所見（デモ＝仕様なので、これがそのまま学習の仕様になる）**

| 論文の所見 | 出典 | 本作での扱い |
|---|---|---|
| **gaze は joint attention の印**。"looking at the user like how humans engage with each other" が無いと "a lack of connection" | §6 (P15) | **接近前と後に顔を見る**。親しみの最大要因 |
| "作業後にこっちを見て『これでいい？』と聞いてるみたいなのが良かった" | §5.2.2 (P7) | スリスリ後の見上げ |
| 対象に向かう前に**まず頭だけ向ける**＝意図の表明 | §3.2.2 Intention | 「溜め」の正体 |
| 動かないロボットは "kinda creepy, as if it was intently staring" | §5.2.1 (P7) | expressive は静止させない。**functional はあえて静止**させて対比に使う |
| 理由のない動きは "a lack of attention on the robot's part" | §5.2.3 | アイドルは「手を探す」スキャン |
| "quick and easy to interpret" が好まれ subtle は評価が割れる | §5.2.3 | 2条件の差を大きく取る |
| 誇張しすぎは "distracting or disturbing" | §5.2.3 | はずみは2〜3回まで |
| 能力とのミスマッチは即座に嘘に見える | §5.2.3 (P14, P20) | 目玉シールは wrist cam の横。追従を実際に学習させる |
| モーター音が気になる | §5.2.4 (P12) | **動画は音ありで撮る**。条件差が音でも伝わる |

**発表時の注意（§5.1 Fig.9）**: ロボット研究者は非研究者より表現的ロボットを**低く**評価する (p=0.006)。
キャラクターデザイン/アニメ経験者も有意に低い。高齢なほど低い。
→ 審査員がロボット研究者寄りなら「可愛い」だけでは刺さらない。技術的主張を先に明示する。
